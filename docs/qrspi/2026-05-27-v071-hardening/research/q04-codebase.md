# Q4: What paths and glob patterns does the repo's `.gitignore` currently match, and what categories of generated artifacts (test outputs, review staging, broker scratch, lock files) do those entries cover?

## Summary

**TL;DR:** The root `.gitignore` (the only one in the repo) contains four active entries covering three categories: pipeline broker scratch (`.worktrees/`), editor/IDE config (`.vscode/`), and macOS OS metadata (`.DS_Store` and `**/.DS_Store`). None of the named artifact categories — test outputs, review staging, or lock files — are covered by the current entries. A fifth entry, `.codex-prompts/`, was present from the initial `.gitignore` commit but was removed in commit `eea2c6e` (2026-05-04) when the Codex prompt-file staging mechanism was retired.

**Key findings:**
- The `.gitignore` file is a single root-level file at `/.gitignore`; there are no sub-directory `.gitignore` files anywhere in the repo.
- **Active entries (4):**
  1. `.worktrees/` — matches the top-level git worktree directory created by the qrspi pipeline for per-task subagent isolation. This directory does not currently exist on disk (no active worktrees).
  2. `.vscode/` — matches the VS Code / IDE settings directory. Added in commit `720bc56` (2026-05-02) to exclude per-user IDE config such as `claudeCode.allowDangerouslySkipPermissions`.
  3. `.DS_Store` — matches macOS Finder metadata at the root.
  4. `**/.DS_Store` — glob pattern matching macOS metadata files at any depth in the tree. Three such files are currently ignored on disk: `.DS_Store`, `docs/.DS_Store`, `docs/qrspi/.DS_Store`.
- **Historical entry (removed):** `.codex-prompts/` was added in the initial `.gitignore` commit (`4d6d2f1`, 2026-05-02) to exclude per-task Codex reviewer prompt staging directories written inside worktrees at `.worktrees/{slug}/task-NN/.codex-prompts/`. It was removed in `eea2c6e` (2026-05-04) when PR #110 ("all subagents in agent files") retired the file-based Codex prompt dispatch in favor of a stdin-pipeline form, eliminating the scratch directories entirely.
- **Not covered by any current entry:** test outputs, review staging directories, lock files (`*.lock`, `Pipfile.lock`, `package-lock.json`, etc.). No such files were found on disk in the repo either.

**Surprises:** The `.codex-prompts/` entry was removed rather than kept as a safety net. Its removal was explicitly called out in the migration plan (`docs/superpowers/plans/2026-05-04-110-subagents-in-agent-files.md:982`) and design spec (`docs/superpowers/specs/2026-05-04-110-subagents-in-agent-files-design.md:615`) as a deliberate cleanup step, not merely incidental.

**Caveats:** Investigation was limited to the single root `.gitignore`; no `.gitattributes` or `.git/info/exclude` files were checked for additional ignore patterns. Lock files and test outputs were searched on disk (`find`) but not found, so their absence from `.gitignore` may simply reflect that no such artifacts are generated by this repo's toolchain.

### Historical entry: `.codex-prompts/`

**Introduced:** commit `4d6d2f1` (2026-05-02, initial `.gitignore`).

**Purpose:** The `skills/implement/SKILL.md` (around lines 344–378) dispatched Codex reviewer subagents by writing prompt files to a per-task scratch directory at `.worktrees/{slug}/task-NN/.codex-prompts/codex-prompt-task-{NN}-{reviewer}.md`. These files were ephemeral broker scratch; the `.codex-prompts/` ignore entry prevented them from appearing as untracked files inside a worktree's working tree.

**Removed:** commit `eea2c6e` (2026-05-04), PR #110. The migration from prompt-file-based Codex dispatch to stdin-pipeline form eliminated the `.codex-prompts/` directory creation entirely. The removal was explicitly planned:

> "The `.codex-prompts/` scratch directory is no longer created. The per-task `rm .codex-prompts/...` cleanup goes away. Remove the `.gitignore` entry for `.codex-prompts/`."
> — `docs/superpowers/plans/2026-05-04-110-subagents-in-agent-files.md:982`
