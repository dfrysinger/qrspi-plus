T12 test expectations contain only documentation-shape assertions and no behavioral test. All five T12 bullets check that the Plan-skill SKILL.md "emits" or "states" or "documents" various rules. There is no BATS pin cited for T12 (the related pin is in T13's `test-tdd-dispatch-order.bats`), and the T13 pin covers dispatch order behavior. But T12 specifically concerns the `task_type:` defaulting rule in the Plan template.

The critical missing behavioral test is: when a Plan-skill run emits a task spec for a task with NO `task_type:` field, that spec is treated as TDD by the downstream Implement orchestrator — but T12's test expectations do not include an assertion that a task spec GENERATED by the Plan skill WITH an absent `task_type:` field actually causes the TDD path to be taken by T11's gate (not merely that the prose says it). T12's last bullet "The edit is confined to the per-task spec template and `task_type:` field documentation (no changes to post-approval split orchestration)" is a scope-confinement check, not a behavioral test.

The design.md G6 test strategy requires a "Lightweight bypass test: a task with `task_type: lightweight` produces only the lightweight implementer dispatch. No test-writer dispatch." T13 covers dispatch-order for `task_type: code` and absent `task_type:`, and the `lightweight` bypass — but the T12 test expectations themselves do not cross-reference T13's pin as their behavioral coverage. The test expectations should either explicitly cross-reference T13's behavioral pin as the behavioral test for T12's `task_type:` defaulting, OR add one behavioral test expectation inline. Without this, T12's test expectations are all documentation-shape only with no named behavioral observation, which is not verifiable beyond grep-and-check.
