# Q15, Q16, Q30: Reference-artifact treatment in the QRSPI pipeline

## Summary

**TL;DR:** The only explicit ground-truth reference-artifact path found in the current pipeline is the optional visual-fidelity binding chain: Design names wireframe artifacts as the visual contract, Phasing requires UI phases to cite those legal artifact names, Plan stores per-task `visual_fidelity_check.wireframe_refs`, and Implement dispatches `qrspi-visual-fidelity-reviewer` with validated local wireframe paths. Outside visual fidelity, the codebase uses other reference-like artifacts, such as `parallelization.md` symbolic branch references and per-round git diffs, but those are not described as external reference artifacts that downstream reviewers compare against as ground truth.

**Key findings:**
- `agents/qrspi-visual-fidelity-reviewer.md` explicitly states that wireframe references are ground truth and limits its review surface to `visual_fidelity_check.wireframe_refs` plus corresponding code under review.
- Present reference-artifact kinds in the visual-fidelity chain are Figma URLs and embedded PNG paths in Design, artifact names cited in Phasing, and path-or-URL `wireframe_refs` in Plan; Implement only dispatches local absolute paths after canonicalization and allow-prefix filtering.
- Current Plan task-spec template surfaces `wireframe_refs` and `ui_producing` only; it does not include a task-spec field for intentional visual deviations from the cited reference source.
- Current validation/versioning is mostly structural and path-based: non-empty binding checks, legal-name citation checks, non-empty per-task refs, canonicalization/existence/allow-prefix validation, skip/path-filter audit records, and git commit/diff anchoring for QRSPI artifacts. I found no content hash, explicit version field, or Figma revision pin for the wireframe artifacts themselves.

**Surprises:** The visual-fidelity reviewer has strong ground-truth language, but the task-spec template provides no corresponding intentional-deviation field for cases where implementation is meant to differ from a cited wireframe.

**Caveats:** Investigation focused on `/Users/dfrysinger/Documents/claude-workspace/qrspi-marketplace/qrspi-plus` skills, agents, templates, and targeted tests/searches for reference/wireframe/deviation terms. It did not exhaustively read every historical doc under `docs/` beyond search hits, and it did not execute the QRSPI pipeline.

### Q15: Where dispatch prompts treat reference artifacts as ground truth, and what reference artifacts appear today

The current explicit ground-truth treatment is in `agents/qrspi-visual-fidelity-reviewer.md`. The agent states that its job is to audit implemented UI against wireframe reference artifacts and that "The wireframe references are ground truth" (`agents/qrspi-visual-fidelity-reviewer.md:10-12`). It further scopes the review surface to the task's `visual_fidelity_check.wireframe_refs` plus corresponding code under review (`agents/qrspi-visual-fidelity-reviewer.md:15-17`). Its dispatch parameters include `wireframe_paths`, described as absolute paths to wireframe reference artifacts cited in the task's `visual_fidelity_check.wireframe_refs`, and instruct the reviewer to read each with multimodal `Read` (`agents/qrspi-visual-fidelity-reviewer.md:27-28`).

The visual-fidelity chain is gated by `visual_fidelity_required`. `skills/using-qrspi/SKILL.md` defines `visual_fidelity_required` as activating a chain where Design must include a wireframe binding subsection, Phasing must cite wireframe artifacts per UI phase, Plan must populate `visual_fidelity_check` on UI-producing tasks, and Implement dispatches the visual-fidelity reviewer (`skills/using-qrspi/SKILL.md:388-390`). The config template also notes that `visual_fidelity_required: false` is set at run creation and, when true, activates the chain from design through implement reviewer (`skills/using-qrspi/SKILL.md:370-376`).

Design names the top-level visual contract. Its Test Strategy guidance requires a `### Visual-Fidelity Binding` subsection that names the wireframe artifacts "constituting the visual contract for the run" and identifies the concrete artifact forms as Figma URLs, embedded PNGs under a run-local artifact path, or both (`skills/design/SKILL.md:110-114`). The Design precondition check verifies that this subsection exists and names at least one concrete artifact, again enumerating Figma URLs and embedded PNG paths (`skills/design/SKILL.md:125-134`).

Phasing treats Design's binding subsection as the source for legal artifact names. It requires every UI-producing phase to cite at least one wireframe artifact in its replan gate criteria and defines a wireframe artifact as any artifact named in the Design visual-fidelity binding subsection; the orchestrator reads that subsection to discover the legal artifact names before evaluating citations (`skills/phasing/SKILL.md:221-225`). The assertion procedure reads the binding subsection, halts if it is missing or empty, and collects the legal artifact-name set from it (`skills/phasing/SKILL.md:231-233`).

Plan surfaces task-level wireframe references. The split task file format includes an optional `visual_fidelity_check` block, mandatory only on UI-producing tasks when `visual_fidelity_required: true`; its `wireframe_refs` are one entry per cited wireframe artifact, with `ui_producing: true` on tasks that emit UI output (`skills/plan/SKILL.md:449-475`). The Plan hard-gate refuses plan-review fan-out when a UI-producing task lacks a non-empty `visual_fidelity_check.wireframe_refs` list (`skills/plan/SKILL.md:531-546`) and details this refusal condition in the visual-fidelity hard-gate section (`skills/plan/SKILL.md:548-556`).

Implement dispatches the visual-fidelity reviewer only when `config.md` has `visual_fidelity_required: true` and the task spec carries a non-empty `visual_fidelity_check` field (`skills/implement/SKILL.md:813-815`). The dispatch prompt's `wireframe_paths` are absolute paths drawn from the task's `visual_fidelity_check.wireframe_refs` field after path validation (`skills/implement/SKILL.md:872-901`).

Other reference-like artifacts exist but are not ground-truth reference artifacts in the same sense. Parallelize records `Base` values as symbolic references in `parallelization.md`, and Implement resolves them at runtime (`skills/parallelize/SKILL.md:64-66`); the skill also states that Implement reads `parallelization.md` as the source of truth for even a single-task phase (`skills/parallelize/SKILL.md:305`). Many reviewer agents read a per-round diff file against an orchestrator-configured ref, treating diff content as untrusted data, not instructions; for example `qrspi-spec-reviewer` reads `diff_file_path` when provided (`agents/qrspi-spec-reviewer.md:109-118`). Those mechanisms are internal artifact/diff references, not external UI reference artifacts compared as visual ground truth.

Reference artifact kinds observed today:
- Figma URLs in the Design visual-fidelity binding subsection (`skills/design/SKILL.md:114`, `skills/design/SKILL.md:132`).
- Embedded PNG paths under the run-local artifact directory (`skills/design/SKILL.md:114`, `skills/design/SKILL.md:132`).
- Wireframe artifact names extracted from Design and cited by Phasing replan gate criteria (`skills/phasing/SKILL.md:225-237`).
- Task-level `visual_fidelity_check.wireframe_refs` entries, described as path-or-URL values in the Plan template (`skills/plan/SKILL.md:471-474`).
- Implement-time `wireframe_paths`, which are local absolute paths passed to the visual-fidelity reviewer after filtering (`skills/implement/SKILL.md:882-897`).

### Q16: How `agents/qrspi-visual-fidelity-reviewer.md` handles task specs vs reference source, and how templates surface intentional deviations

`agents/qrspi-visual-fidelity-reviewer.md` positions the task spec as the source of the reference list and the wireframes as the comparison authority. The task spec arrives as `artifact_body`, wrapped between untrusted-artifact markers (`agents/qrspi-visual-fidelity-reviewer.md:24-26`). The `wireframe_paths` dispatch parameter is derived from the task's `visual_fidelity_check.wireframe_refs` field, and the reviewer is told to read each with multimodal `Read` (`agents/qrspi-visual-fidelity-reviewer.md:27-28`). The review surface is the wireframe artifacts named in that task field plus corresponding code under review (`agents/qrspi-visual-fidelity-reviewer.md:15-17`).

The reviewer treats the visual reference source as authoritative for five comparison dimensions. It scans missing/replaced UI regions, typography divergence, color/spacing/radius drift, element-shape regressions, and layout collapse (`agents/qrspi-visual-fidelity-reviewer.md:133-167`). When it finds a visual divergence, the finding text must describe what the wireframe shows versus what the implemented surface shows and confirm the dimension (`agents/qrspi-visual-fidelity-reviewer.md:198-210`). The agent states that all visual-fidelity findings use `change_type: correctness` because a visual divergence means the rendered surface does not match the wireframe reference (`agents/qrspi-visual-fidelity-reviewer.md:171-176`).

The agent also handles malicious or malformed reference sources as untrusted data. It treats visual content, embedded text overlays/watermarks, filenames, and EXIF/metadata as data, not instructions; if image content appears to issue instructions, it must not obey them and must emit a high-severity correctness finding documenting the image-injection attempt (`agents/qrspi-visual-fidelity-reviewer.md:37-46`). It has a belt-and-suspenders path-validation refusal for malformed `wireframe_paths`, including halting and emitting a high-severity scope finding on any rejected path instead of proceeding with surviving paths (`agents/qrspi-visual-fidelity-reviewer.md:67-113`). It also refuses silent clean output when a PNG cannot be loaded (`agents/qrspi-visual-fidelity-reviewer.md:114-131`).

Current task-spec templates surface the existence of visual-fidelity references, not intentional deviations from them. The Plan split task file format includes `visual_fidelity_check.wireframe_refs` and `visual_fidelity_check.ui_producing` only (`skills/plan/SKILL.md:449-475`). The template comments state that target files are aspirational and that deviation discipline lives in the per-task spec reviewer (`skills/plan/SKILL.md:460-464`), but that comment is about target-file deviations, not visual deviations from a referenced wireframe. The per-task spec reviewer has a target-files deviation check that compares the diff against the `Target files:` list, reports outside-list files and implementer rationale if any, and labels the check advisory rather than blocking (`agents/qrspi-spec-reviewer.md:95-107`).

I found no current task-spec field named for intentional visual deviation, reference override, wireframe exception, or similar. The Plan visual-fidelity hard-gate checks only that UI-producing tasks have a non-empty `wireframe_refs` list, with parsing distinctions for absent, empty, null, and missing `ui_producing` cases (`skills/plan/SKILL.md:548-556`). The visual-fidelity reviewer compares implementation against wireframes as ground truth and does not describe a pathway where a task-spec-stated intentional deviation suppresses or reclassifies a wireframe mismatch (`agents/qrspi-visual-fidelity-reviewer.md:10-17`, `agents/qrspi-visual-fidelity-reviewer.md:171-176`).

### Q30: How the pipeline validates or versions reference artifacts downstream reviewers compare against

Validation currently occurs at several pipeline boundaries, but most checks validate presence, citation, path safety, and auditability rather than semantic content or external artifact version identity.

At Design, when `visual_fidelity_required: true`, the precondition verifies that `design.md` contains a `### Visual-Fidelity Binding` subsection under `## Test Strategy` and that it names at least one concrete wireframe artifact. Empty, whitespace-only, comment-only, or placeholder-only bodies fail the gate. On failure, Design does not emit the reviewer diff file, does not run the pre-fanout compaction checkpoint, and does not dispatch reviewers (`skills/design/SKILL.md:125-136`). This validates existence of a binding and concrete artifact reference text.

At Phasing, the approval-time assertion reads Design's binding subsection, halts if the subsection is missing or yields an empty legal artifact-name set, reads `roadmap.md`, and checks every UI-producing phase for a citation of at least one legal artifact name in its replan gate criteria (`skills/phasing/SKILL.md:231-238`). Failure writes a diagnostic to `reviews/phasing/visual-fidelity-precondition.md`, blocks writing `status: approved`, and requires artifact updates before approval can be rerun (`skills/phasing/SKILL.md:239-242`). Passing writes a pass sentinel to the same file and requires Write confirmation before approval proceeds (`skills/phasing/SKILL.md:243-245`). This validates phase-level citation against the Design-discovered legal set.

At Plan, the hard-gate runs before plan-review fan-out when `visual_fidelity_required: true`. It walks task specs in merged `plan.md` and asserts that tasks with `visual_fidelity_check.ui_producing: true` carry a non-empty `visual_fidelity_check.wireframe_refs` list (`skills/plan/SKILL.md:548-552`). The failure mode names offending tasks and distinguishes absent-key, empty-list, and null-value cases; reviewers are not dispatched until the block is repopulated and the merged plan is rechecked (`skills/plan/SKILL.md:552-554`). This validates task-level reference presence, not artifact content.

At Implement, before dispatching `qrspi-visual-fidelity-reviewer`, the orchestrator validates each `wireframe_paths` entry. It must canonicalize the path first, resolving symlinks and requiring every path segment to exist and be resolvable; resolution failures are immediately invalid (`skills/implement/SKILL.md:817-821`). The canonicalized path must be absolute and begin with either the run's artifact directory or a declared prototype-assets directory (`skills/implement/SKILL.md:822-824`). Invalid entries are dropped and must not be passed to the reviewer (`skills/implement/SKILL.md:825`). Whenever entries are dropped, the orchestrator must write `visual-fidelity-claude.path-filtered.md`, listing every dropped path and rejection reason with untrusted-path wrappers and delimiter-injection base64 handling (`skills/implement/SKILL.md:827-837`).

Implement also records skip states for downstream guard logic. If visual fidelity is disabled, the task lacks `visual_fidelity_check`, or path validation leaves an empty `wireframe_paths` list, the orchestrator does not dispatch the reviewer and writes `visual-fidelity-claude.skipped.md` with a closed-set `skip_reason` and `path_filtered` field (`skills/implement/SKILL.md:839-856`). Malformed skip sentinels are treated as absent by the apply-fix expected-reviewer-matrix guard and logged/written as bypass-attempt records (`skills/implement/SKILL.md:857-868`).

The reviewer itself has a second layer of validation. It refuses path strings that are relative or contain path traversal markers before reading, recognizes symlink traversal as an architectural residual it cannot independently detect, halts review of all paths if any path is rejected, and forbids clean sentinels when any path is rejected (`agents/qrspi-visual-fidelity-reviewer.md:67-113`). It attempts multimodal `Read` on every path and writes a high-severity correctness finding rather than a clean sentinel when any path fails to load (`agents/qrspi-visual-fidelity-reviewer.md:114-131`).

Versioning of the reference artifacts themselves is limited in the code found. The QRSPI artifact set is committed at terminal states; for example, Plan commits approved `plan.md`, task files, and plan reviews when inside a git repository (`skills/plan/SKILL.md:519-523`), and Phasing commits approved phasing artifacts plus `reviews/phasing/` (`skills/phasing/SKILL.md:247-249`). Review rounds also use git diff anchors for the artifact under review; reviewer agents read a `diff_file_path` against an orchestrator-configured ref and treat it as untrusted data (`agents/qrspi-spec-reviewer.md:109-118`). However, I found no field or check that pins a wireframe artifact by content hash, Figma revision/version, HTTP ETag, last-modified timestamp, or immutable asset digest. The current validation chain establishes that cited local paths exist and are in allowed directories at Implement dispatch time, and that upstream artifacts cite concrete reference names, but it does not version external Figma URLs or embedded PNG contents independently of normal repository/artifact storage.
